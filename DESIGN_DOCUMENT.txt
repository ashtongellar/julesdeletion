## 2. Core Problem Analysis
(As before) The core issue is the slowness and instability of file deletion on Windows, caused by GUI overhead, NTFS metadata operations, and antivirus scanning. The script aims to bypass the GUI and perform deletions in a stable, one-by-one manner.

## 3. Technical Decisions & Justifications
- **Architecture:** The two-phase "log-then-delete" model remains for robustness.
- **Discovery/Sort:** The "discover-then-sort" method is the most reliable way to guarantee correct deletion order and prevent hangs.
- **Deletion:** Concurrent deletion via `ThreadPoolExecutor` and `rm` meets user requirements for scalability and stability.
- **Documentation:** Line-by-line comments and this design document fulfill the user's requirement for a self-debugging implementation.
